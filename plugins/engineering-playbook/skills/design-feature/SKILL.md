---
name: design-feature
description: Design a non-trivial feature with domain analysis, architecture trade-offs and OpenSpec before implementation.
---
1. Read project instructions, relevant code and `openspec/config.yaml`.
2. Clarify observable behavior, acceptance criteria, constraints and failure modes.
3. Inspect existing domain language before proposing abstractions.
4. For non-trivial changes, use OpenSpec to produce proposal, specs, design and tasks.
5. Consult `software-architect` for cross-boundary design and `ddd-domain-expert` for domain modeling.
6. Identify persistence/API changes, security, observability, rollout and rollback.
7. Present consequential decisions and open questions before implementation.
